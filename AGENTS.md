# Control Box agent notes

Control Box is a local Mac app that maps unusual input devices (DualSense, Apple TV remote, Logitech MX Master) to pointer, keys, and system gestures.

## Current status (2026-08-27)

- Multi-device is live: DualSense, Apple TV remote, MX Master 3/3S, and MX Master 4 can stay attached at once. Each device has its own **Control this Mac** toggle.
- Device I/O lives in family sessions (`DeviceFamilySession`): `DualSenseSession`, `AppleTVRemoteSession` (generation `AppleTVA2540`), MX 3/3S and MX 4 readers. The host (`DualSenseMonitor`) is records, engines, and the poll loop. Add a family; do not add `captureXbox()` on the host.
- HID modules stay split: **3/3S together** (`MXMaster3Support`) and **4** (`MXMaster4Support`). Each family has its own HID++ reader (product IDs only). Shared code is the HID++ pipe and hold-to-swipe engine.
- 3S HID++ is nested on the mouse device (page `0xFF43`, report `0x11`). Gesture is thumb CID `0x00C3`. See `dev/mx-master-3s-hid.md`.
- MX4 pointer / haptic stack is unchanged. How MX4 should feel is `dev/mx-master-4-pointer-and-haptic.md`.
- Pointer speed and gesture speed are **separate sliders**. DPI is sensor resolution only. Both speeds divide out DPI so 1000 DPI is the reference feel.
- 3S: tap gesture button = click action; hold 100ms then move = swipe. Same ControlEngine path as MX4 haptic (owner `.mxHaptic`).
- DualSense touchpad: **1-finger** and **2-finger** are separate Gestures owners (`touchpadOneFinger` / `touchpadTwoFinger`). Same `HoldGesture` path as MX. Physical click stays `touchpadClick`. Finger count can promote to 2-finger during the 100ms arm window, then locks.
- DualSense L2/R2 mapped to Previous/Next tab use analog travel (mid = one tab, full hold = repeat). L1/R1 stay digital. Other devices unchanged.
- Factory defaults match the live desk: DualSense L1/R1 desktops, L2/R2 tabs, D-pad Mission Control / Desktop / app switch, Square click, 1-finger media, left stick pointer / right stick scroll; Apple TV Back = Return; MX pointer 21%, natural scroll off, Mode shift = Right Option; MX4 haptic 61% and 4000 DPI.
- **Display Brightness** is the Mac pane for per-panel brightness (and contrast on supported externals). Optional **One slider for all displays** snapshots each panel’s mix when enabled, fades the per-panel brightness sliders, and scales them from one master (0% all dark, 100% previous brightest at full). Optional **Show in menu bar** adds a sun extra with those sliders (off until the toggle is on). Hide of that extra does not quit Control Box.
- **Sound** is a Mac pane (output + per-app volume). Optional **Show in menu bar** adds a speaker extra with the same sliders. Off until the toggle is on. Hide does not quit Control Box.
- **Display Arrangement** is its own Mac pane (not brightness). Presets are keyed by the connected external combo plus whether the built-in panel is in the layout. Same physical panels (serial / UUID) collapse to one group even if an older key format is stored. Apply is exact-match only; the editor is a sandbox. Keyboard shortcut is a 3+ modifier chord plus number/arrows, HUD shows the layout snapshot, and that chord cannot match Window Management move, resize, or throw. Organize is a recorded shortcut and only conflicts if it uses the same modifiers plus 1–9 or arrows. The shortcut catalog lives on the app delegate so the tap survives window close. See DisplayArrangement.swift.
- **Night Shift** is its own Mac pane. Off until the pane toggle is on. Then a 24-hour warmth curve drives system Night Shift (`CBBlueLightClient`); Apple’s sunset schedule is paused and restored when the toggle goes off. Take-over is a custom 00:00–23:59 schedule because Tahoe rejects `setMode(off)`. While the pane is on, Control Box hijacks system Night Shift: System Settings / Control Center changes are put back on the curve. Optional **Also adjust external brightness** swings external monitors with the curve (cool → brighter, warm → dimmer) by a user slider defaulting to ±10%. Built-in brightness is left alone. The catalog lives on the app delegate so the timer survives window close.
- **System Monitor** (`top`, vendored in `ControlBox/Top`) is its own Mac pane. Off until the pane toggle is on. When on, it adds a **second** menu bar extra (live ↑/↓ network icon + dashboard `NSMenu`), not the Control Box ring extra. Hide/quit of that extra does not quit Control Box. WidgetKit from upstream is not in this app.
- **Permissions** has **Launch at Login** (`SMAppService.mainApp`) and **Hide Dock icon**. Command-Q closes the window and leaves the app running. Quit is only on the Control Box menu bar extra. Logout still quits.
- **Window Management** is a Mac pane: hold Control and move to drag a window from anywhere; hold Control+Shift and move to resize with the top-left anchored. Optional **Throw** (default Control+Option, off until the toggle is on) snaps the window under the cursor to a 3×3 map of the pointer’s screen (corners = quarters, edges = halves, center = full). Optional **Organize** (default Control-Command-O, off until the toggle is on) is a recorded shortcut (modifiers plus a key) that tiles visible windows on that screen. Optional **Shake to focus** (off until the toggle is on) hides every other visible window when you shake one; a second shake restores them. Optional **Minimize on Dock click** (off until the toggle is on) minimizes that app’s visible window when you click its Dock icon and the app is already front. Shake scope is **This display** or **All displays** (physical monitors, not Spaces). Works with the trackpad, any mouse, or DualSense. Accessibility must be on. Not gated on an MX Master. Move, resize, throw, and Display Arrangement cannot share an exact modifier set; Organize cannot reuse Display Arrangement’s number/arrow keys with the same modifiers. The picker alerts and refuses a collision. See [dev/shake-to-focus.md](dev/shake-to-focus.md).
- **Caps Lock** is its own Mac pane. Off until the pane toggle is on. Then Caps Lock is a hold key that synthesizes a chosen modifier chord (default Control) for Control Box only — not a caps toggle and not a system Hyper key. A `defaultTap` swallows keycode 57; HID usage `0x39` tracks physical hold. `ModifierChords.live()` ignores lock-state Caps Lock and ORs in the mapped modifiers while the key is held. Catalog lives on the app delegate so the tap survives window close. See [dev/caps-lock-modifier.md](dev/caps-lock-modifier.md).
- **Dock Previews** is its own Mac pane. Off until the pane toggle is on. Hover a Dock icon that has open windows to see them (including minimized and other Spaces — virtual desktops, not other displays) and click a card to focus that window, or × to close it, or power to quit the app. Apps with no windows stay native — no empty card. Card size is a slider, default 130%. Optional **Show window previews in the app switcher** (own size slider up to 300%; off until that toggle is on) shows the same cards while Command-Tab is up, without the title line or HUD, always on the main display between the switcher strip and the top of the display. Optional **Show Dock icon names** snapshots and clears pinned `com.apple.dock` `file-label` strings (restore when the toggle is on). Do not `killall Dock`. Always use the flat panel chrome — no callout shape. Hide while a Dock right-click menu is open. Works on whichever display currently has the Dock; place from the icon AX frame, not a hardcoded point. Do not pin Dock auto-hide. Liquid Glass chrome. Catalog lives on the app delegate so hover survives window close. Accessibility finds Dock icons; Screen Recording is optional for thumbnails and is not the Sound audio grant. Hide the panel while Window Management is held or Shake to focus is watching a drag. Do not intercept native Dock clicks. See [dev/dock-window-preview.md](dev/dock-window-preview.md), [dev/app-switcher-window-preview.md](dev/app-switcher-window-preview.md).
- **MX Gestures is the 3S gesture button / MX4 haptic pad only.** Click-as-gesture on Back / Forward / etc. is still parked. DualSense finger rows are allowed.
- **Pointer & Scroll** is a Mac pane (pointer speed, wheel/thumb speed, smooth scrolling, direction). Not gated on an MX Master. Pointer speed applies to USB/Bluetooth mice; DualSense and Siri Remote keep device-page sliders.
- With **Allow while Control Box is focused** off, a frontmost Control Box window skips **device** injection (gestures, thumb HID++ scroll, buttons). Window grab is a Mac shortcut and still runs. System-navigation is not a bypass. See `dev/focused-host-still-injects.md`.
- MX wheel and thumb roller are **per-direction** bindings (`mxWheelUp/Down`, `mxThumbLeft/Right`). Missing or `.scroll` keeps native scroll for that direction; any other action replaces it (`MouseScrollTap` drop flags).
- MX Calibration is a silhouette mouse plus a separate gesture pad. Wheel column is **Up, Click, Down**, then a gap, then **Mode**. Thumb is Forward above Back. MX4-only **Side** sits between the thumb roller and Forward.
- MX4 left / right / wheel on Calibration come from report `0x02` on the HID++ device plus **one** shared `CGEvent` tap. Do not open the mouse collection; do not give each reader its own tap. See `dev/mx4-clicks-missing-in-calibration.md`.
- Do not attach Bolt receiver `C548`. Do not seize HID. Do not open the standard mouse collection just to watch buttons. Do not go back to one matcher for every Logitech interface.

## Device rule

Treat these as **different devices**, not one “MX Master”:

| Device | HID++ collection | Gesture / extra-button notes |
|---|---|---|
| MX Master 3 | Unifying `0x4082`, BLE `0xB023`. Same HID module as 3S. | Gesture CID `0x00C3`. No 3 on this Mac; inferred from Solaar/logiops. |
| MX Master 3S | BLE `0xB034`, Bolt `0xB043`. Nested `0xFF43` / report `0x11`. | Same CIDs as Master 3. Thumb gesture `0x00C3`. |
| MX Master 4 | BLE: vendor report `0x11` on the mouse device (page `0xFF43`), not a separate `0xFF00` collection. Bolt receiver `C548` is not the mouse. | Haptic is HID button 7 (`0x40` on report `0x02`). CID `0x01A0` is HID++ when that pipe exists. Extra thumb **Side** button is CID `0x00C3` (in front of Back / Forward). |

3S + 4 at once is allowed through **two isolated readers**, not one manager that opens every Logitech collection. Keep 3/3S and 4 as separate HID modules. Shared code should stay at “send a HID++ report” / “list HID devices” / hold-to-swipe.

## Hard constraints

- Never call `IOBluetoothDevice.pairedDevices()`. It has corrupted the heap on this Mac (`libmalloc` / `EXC_BREAKPOINT`).
- Never `IOHIDManagerOpen` with `kIOHIDOptionsTypeSeizeDevice` on Logitech mouse or HID++ managers.
- Do not open the standard Logitech mouse collection (usage page `0x01` usage `0x02`) just to watch buttons. That can steal the system pointer.
- Reprog Controls V4 `setCidReporting` flags are value + valid pairs, not “0x01 divert / 0x02 persist / 0x04 raw XY”. Solaar hold-only gestures use **`0x33`** (divert+valid + rawXY+valid). Persist is `0x04`/`0x08`. Force raw XY is `0x40`/`0x80`. Packet is CID, flags, remap, and optional high flags. Analytics reporting is high-byte `0x03`. Do not send persist or force-raw-XY. Clear with `0x22`, not `0`. The Master 4 haptic pad also needs Force Sensing `0x19C0` threshold `0x15A3`; press events often arrive as analytics, not diverted-buttons.
- Debug builds must stay signed with the Apple Development identity (`DEVELOPMENT_TEAM = XXA24FWXDW`) so Accessibility and Input Monitoring persist across rebuilds. Do not switch back to ad-hoc (`CODE_SIGN_IDENTITY = "-"`).
- Never upload or publish without explicit approval.
