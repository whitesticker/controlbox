# Control Box agent notes

Control Box is a local Mac app that maps unusual input devices (DualSense, Apple TV remote, Logitech MX Master, MX Mechanical) to pointer, keys, and system gestures.

## Current status (2026-09-09)

- Multi-device is live: DualSense, generic Game Controller pads, Apple TV remote, MX Master 3/3S, MX Master 4, and **MX Mechanical / Mini** can stay attached at once. Mice have a **Control this Mac** toggle. A device is on the **sidebar** only after **Add** on Add Device (existing settings → **Settings**). Delete Device removes that row even if it is still connected. MX, DualSense, generic gamepads, and Apple TV Remote device pages use a **Profiles** card with wrapping **profile tiles** (Default, per-app tiles, Add App) whose mappings follow the frontmost app (`NSWorkspace.didActivateApplicationNotification`). On DualSense, generic gamepads, and Apple TV Remote, only button and gesture mappings are per-app. **Analog**, **Pointer & Scroll**, and **Calibration** stay outside Profiles as device-level settings. DualSense **Tab repeat** is on Calibration and is also device-level. Adding a known browser or editor starts from a preset on MX and DualSense; there is no Browsers / Editors category. MX mice also have MagSpeed **Free Spin / Ratchet** plus SmartShift sensitivity on **Mouse Settings** (`0x2111`, fallback `0x2110`); buttons can map **Switch wheel mode** to toggle it. See `dev/mx-smartshift.md`. The keyboard family is settings-only (backlight, lighting effect, battery saving, battery %). **Logi Bolt** is Add Device → Logi Bolt (vendor HID++ on `C548` only): pair/unpair plus Bolt-only talk on that same pipe (slot HID++ 2.0). The same mouse or keyboard on BLE and Bolt is one sidebar row; BLE wins when both radios are up. MX **device pages** show Easy-Switch **channels** (`0x1814` / `0x1815`, three tiles, Refresh, Pending until HID++ answers). **Name** is a Control Box nickname plus HID++ friendly name `0x0007` on MX. Battery HID++ is every 5 minutes.
- Generic game controllers: `GamepadSession` (GameController `GCExtendedGamepad`) is the base; `DualSenseSession` subclasses it for touchpad + HID battery. Any pad macOS recognises is Add Device → Bluetooth with kind `.gamepad`; labels follow `GamepadLayout`. Touchpad / motion / haptics are capabilities, not the base. See `dev/generic-gamepad.md`.
- Device I/O lives in family sessions (`DeviceFamilySession`): `GamepadSession` (generic `GCExtendedGamepad`), `DualSenseSession` (subclass for touchpad + HID battery), `AppleTVRemoteSession` (generation `AppleTVA2540`), `MXKeyboardSession`, and `LogitechDeviceSession`. The host (`DualSenseMonitor`) is records, engines, and the poll loop. Add a family; do not add `captureXbox()` on the host.
- Logitech lifecycle and Bolt routing are grouped behind `LogitechDeviceSession`; the host sees `LogitechMouseDevice` / `LogitechKeyboardDevice`, not concrete MX readers. Shared HID++ 2.0 report encoding, request serialization, feature capabilities, control descriptors, and unified-battery parsing live in `ControlBoxCore/Devices/Logitech/`. Keep transport-specific reply/error policy in the family reader.
- Generic Logitech mice no longer require a model allowlist. The one `LogitechMouseReader` implementation accepts only audited HID++ endpoints that `LogitechHIDPPDiscovery` correlates with a standard mouse collection; known receiver PIDs and keyboard products are excluded. Feature and Reprog control tables gate Easy-Switch, Profiles subcards, Mouse Settings rows, and up to twelve stable Extra controls.
- Logitech mice use one capability-driven module and a pool of per-device `LogitechMouseReader` sessions. `LogitechMouseRegistry` contains only compact identity/fallback quirks for 3/3S and 4; it is data, not a per-model implementation. Keyboard remains `MXMechanicalSupport` (`0xB366` / `0xB367`). `0xB366` is the keyboard, not MX4. See `dev/mx-mechanical-hid.md`.
- 3S HID++ is nested on the mouse device (page `0xFF43`, report `0x11`). Gesture is thumb CID `0x00C3`. See `dev/mx-master-3s-hid.md`.
- MX4 pointer / haptic stack: the **haptic button** still pins and mixes HID++ XY with report `0x02`. The **gesture button** matches OpenLogi (`0x33`, firmware XY only, no pin). See `dev/mx-master-4-pointer-and-haptic.md` and `dev/mx4-gesture-button-freezes-pointer.md`.
- Pointer speed and swipe feel are independent. DPI is sensor resolution only and lives on **Mouse Settings**. Thumb-wheel sensitivity is also on Mouse Settings (software scale of HID++ `0x2150`). Pointer speed and swipe both divide out DPI so 1000 DPI is the reference feel. Pointer and wheel speed are on Mac → Pointer & Scroll (event tap / OS HID) for every USB/Bluetooth mouse.
- 3S: tap the **gesture button** (CID `0x00C3`, owner `.mxSide`) = click action; hold 100ms then move = swipe. MX4 **haptic button** is CID `0x01A0` / `.mxHaptic`. Same ControlEngine HoldGesture path. MX4 **gesture button** is the same CID `0x00C3`; divert it `0x33` (OpenLogi raw XY) and do not pin the pointer. Mode shift can own Gestures the same way.
- DualSense touchpad: **1-finger** and **2-finger** are separate Gestures owners (`touchpadOneFinger` / `touchpadTwoFinger`). Same `HoldGesture` path as MX. Physical click stays `touchpadClick`. Finger count can promote to 2-finger during the 100ms arm window, then locks.
- DualSense L2/R2 mapped to Previous/Next tab use analog travel (mid = one tab, full hold = repeat). L1/R1 stay digital. Other devices unchanged.
- Factory defaults match the live desk: DualSense L1/R1 desktops, L2/R2 tabs, D-pad Mission Control / Desktop / app switch, Square click, 1-finger media, left stick pointer / right stick scroll; Apple TV Back = Return; MX pointer 21%, natural scroll off, Mode shift = Right Option; MX4 4000 DPI.
- **Display Brightness** is the Mac pane for per-panel brightness (and contrast on supported externals). Optional **One slider for all displays** snapshots each panel’s mix when enabled, fades the per-panel brightness sliders, and scales them from one master (0% all dark, 100% previous brightest at full). Optional **Show in menu bar** adds a sun extra with those sliders (off until the toggle is on). Hide of that extra does not quit Control Box.
- **Sound** is a Mac pane (output + per-app volume). Optional **Show in menu bar** adds a speaker extra with the same sliders. Off until the toggle is on. Hide does not quit Control Box.
- **Caffeinate** is a Mac pane that keeps the Mac awake (idle system sleep + idle display sleep). Optional **Show in menu bar** adds a coffee-cup extra. Click the extra for a duration menu (1 minute through 1 day, plus forever). The menu also has **Sleep Now**, which stops Caffeinate and requests immediate system sleep. While a session is on, that menu shows a countdown and Turn Off. Off until the toggle is on. Hide does not quit Control Box. Catalog lives on the app delegate so the assertion survives window close. Lid close can still sleep a MacBook. Quit releases the assertion.
- **Display Arrangement** is its own Mac pane (not brightness). Presets are keyed by the connected external combo plus whether the built-in panel is in the layout. Same physical panels (serial / UUID) collapse to one group even if an older key format is stored. Apply is exact-match only; the editor is a sandbox. Keyboard shortcut is a 3+ modifier chord plus number/arrows, HUD shows the layout snapshot, and that chord cannot match Window Management move, resize, or throw. Organize is a recorded shortcut and only conflicts if it uses the same modifiers plus 1–9 or arrows. The shortcut catalog lives on the app delegate so the tap survives window close. See DisplayArrangement.swift.
- **Night Shift** is its own Mac pane. Off until the pane toggle is on. Then a 24-hour warmth curve drives system Night Shift (`CBBlueLightClient`); Apple’s sunset schedule is paused and restored when the toggle goes off. Take-over is a custom 00:00–23:59 schedule because Tahoe rejects `setMode(off)`. While the pane is on, Control Box hijacks system Night Shift: System Settings / Control Center changes are put back on the curve. Optional **Schedule Light and Dark** (default on) flips appearance at sunset/sunrise or custom hours — Apple Auto cannot stay on because it follows the all-day Night Shift window. Off freezes the current look. Restore Apple Auto when the pane goes off. See [dev/night-shift-flips-dark-mode.md](dev/night-shift-flips-dark-mode.md). Optional **Also adjust external brightness** swings external monitors with the curve (cool → brighter, warm → dimmer) by a user slider defaulting to ±10%. Built-in brightness is left alone. The catalog lives on the app delegate so the timer survives window close.
- **System Monitor** (`top`, vendored in `ControlBox/Mac/SystemMonitor`) is its own Mac pane. Off until the pane toggle is on. When on, it adds a **second** menu bar extra (live ↑/↓ network icon + dashboard `NSMenu`), not the Control Box ring extra. Hide/quit of that extra does not quit Control Box. WidgetKit from upstream is not in this app.
- **Permissions** has **Launch at Login** (`SMAppService.mainApp`). **Settings** (under Permissions) has **Hide Dock icon** and the product page. Command-Q closes the window and leaves the app running. Quit is only on the Control Box menu bar extra. Logout still quits.
- **Window Management** is a Mac pane: hold Control and move to drag a window from anywhere; hold Control+Shift and move to resize with the top-left anchored. Optional **Throw** (default Control+Option, off until the toggle is on) snaps the window under the cursor to a 3×3 map of the pointer’s screen (corners = quarters, edges = halves, center = full). Optional **Organize** (default Control-Command-O, off until the toggle is on) is a recorded shortcut (modifiers plus a key) that tiles visible windows on that screen. Optional **Shake to focus** (off until the toggle is on) hides every other visible window when you shake one; a second shake restores them. Optional **Minimize on Dock click** (off until the toggle is on) minimizes that app’s visible window when you click its Dock icon and the app is already front. Shake scope is **This display** or **All displays** (physical monitors, not Spaces). Works with the trackpad, any mouse, or DualSense. Accessibility must be on. Not gated on an MX Master. Move, resize, throw, and Display Arrangement cannot share an exact modifier set; Organize cannot reuse Display Arrangement’s number/arrow keys with the same modifiers. The picker alerts and refuses a collision. See [dev/shake-to-focus.md](dev/shake-to-focus.md).
- **Caps Lock** is its own Mac pane. Off until the pane toggle is on. Then Caps Lock is a hold key that synthesizes a chosen modifier chord (default Control) for Control Box only — not a caps toggle and not a system Hyper key. A `defaultTap` swallows keycode 57; HID usage `0x39` tracks physical hold. `ModifierChords.live()` ignores lock-state Caps Lock and ORs in the mapped modifiers while the key is held. Catalog lives on the app delegate so the tap survives window close. See [dev/caps-lock-modifier.md](dev/caps-lock-modifier.md).
- **Dock Previews** is its own Mac pane. Off until the pane toggle is on. Hover a Dock icon that has open windows to see them (including minimized and other Spaces — virtual desktops, not other displays) and click a card to focus that window, or × to close it, or power to quit the app. Other-Space cards always show quit (close / minimize need this Space). Do not list inspectors, palettes, or mini widgets as cards — drop non-minimized surfaces smaller than 35% of that app’s largest window on the same display; a nested-only filter is not enough (Calendar’s inspector sits beside the host). Apps with no windows stay native — no empty card. Card size is a slider, default 130%. Optional **Show window previews in the app switcher** (own size slider up to 300%; off until that toggle is on) shows the same cards while Command-Tab is up, without the title line or HUD, always on the main display between the switcher strip and the top of the display. Optional **Show Dock icon names** snapshots and clears pinned `com.apple.dock` `file-label` strings (restore when the toggle is on). Do not `killall Dock`. Always use the flat panel chrome — no callout shape. Hide while a Dock right-click menu is open. Works on whichever display currently has the Dock; place from the icon AX frame, not a hardcoded point. Do not pin Dock auto-hide. Liquid Glass chrome. Catalog lives on the app delegate so hover survives window close. Accessibility finds Dock icons; Screen Recording is optional for thumbnails and is not the Sound audio grant. ScreenCaptureKit is the primary still; if an other-Space window is missing from that list (multi-display Macs), take one `CGWindowListCreateImage` of that window ID — otherwise the card is only the app icon. Hide the panel while Window Management is held or Shake to focus is watching a drag. Do not intercept native Dock clicks. See [dev/dock-window-preview.md](dev/dock-window-preview.md), [dev/dock-preview-lists-window-chrome.md](dev/dock-preview-lists-window-chrome.md), [dev/dock-preview-other-space-icon.md](dev/dock-preview-other-space-icon.md), [dev/app-switcher-window-preview.md](dev/app-switcher-window-preview.md).
- Logitech mouse Gestures may use any divertable control whose Reprog entry advertises raw XY. Defaults are the **gesture button** (CID `0x00C3`, 3/3S/4) and the MX4 **haptic button** (`0x01A0`). Middle, Back, Forward, and Extra controls appear in **Gesture-capable controls** only when supported. Left/right are never gesture owners. Raw XY has no source attribution, so the first held owner wins.
- **Pointer & Scroll** is a Mac pane (pointer speed, wheel speed, smooth scrolling, direction). These intercept the Mac’s reading of the mouse; they are not sensor writes. Not gated on an MX Master. Pointer and wheel speed apply to USB/Bluetooth mice; DualSense and Siri Remote keep device-page sliders. Trackpads stay on System Settings.
- With **Allow while Control Box is focused** off, a frontmost Control Box window skips **device** injection (gestures, thumb HID++ scroll, buttons). Window grab is a Mac shortcut and still runs. System-navigation is not a bypass. See `dev/focused-host-still-injects.md`.
- MX main-wheel mapping is not exposed; it always scrolls vertically. Free Spin / Ratchet and SmartShift sensitivity are firmware writes on Mouse Settings. Buttons (and gesture slots) can map **Switch wheel mode** to toggle Free Spin / Ratchet on that mouse; the HUD shows the new mode. Left and right click are native and are not configurable. The thumb wheel has one per-profile `MXWheelMode`, not separate left/right bindings: Horizontal Scroll (default), Vertical Scroll, Navigate Between Tabs (Control-Tab / Control-Shift-Tab, 1.5× OpenLogi increment threshold), Volume (`SystemVolume.nudge` + volume HUD), non-accelerated Zoom In/Out (`⌘=` / `⌘−` because public macOS APIs cannot inject app-content magnification), Switch Between Desktops (live DockSwipe, quarter-turn per Space at 1×), Switch Between Apps, and None. Pointer & Scroll **Smooth scrolling** eases diverted thumb travel for every thumb mode (OpenLogi 100 ms cubic; scroll posts pixel-continuous phases). Wheel speed in Pointer & Scroll scales native mouse-wheel scroll. Diverted MX thumb travel uses the Mouse Settings **Thumb wheel** slider. The delta-driven `MXWheelActionEngine` stays separate from `ControlEngine` button actions. Old thumb-direction bindings decode only to migrate tabs / volume / desktops / apps. The configurable button order is Middle click, Back, Forward, Mode shift; MX4 **gesture button** is in Other buttons when it is not a Gestures owner. The old extra “DPI” mapping row was a phantom HID++ DPI/ModeShift-family alias and is hidden; DPI itself is sensor resolution on Mouse Settings, not that row.
- MX Calibration is three columns: **Button press mapping**, **Haptic capture** over **Click history**, and **Live clicks**. **Mouse Settings** is a separate window (DPI HID++ `0x2201`, MagSpeed **Free Spin / Ratchet** `0x2111` / `0x2110`, thumb-wheel sensitivity, **Invert thumb wheel**). Open it from the device page next to Calibration. Leaving that device page closes its Calibration window. Wheel column is **Up, Click, Down**, then a gap, then **Mode**. Thumb is Forward above Back. MX4 **gesture button** sits between the thumb roller and Forward.
- MX4 left / right / wheel on Calibration come from report `0x02` on the HID++ device plus **one** shared `CGEvent` tap. Do not open the mouse collection; do not give each reader its own tap. See `dev/mx4-clicks-missing-in-calibration.md`.
- Do not attach Bolt receiver `C548` from the mouse product-ID matchers. Pairing and Bolt-only talk are **Add Device → Logi Bolt** plus one catalog-owned vendor HID++ pipe (`0xFF00` only, no seize). Do not open the standard mouse collection just to watch buttons. Do not go back to one matcher for every Logitech interface.
- Generic discovery may match only `0xFF00/0x0002`, `0xFF43/0x0202`, and `0xFF43/0x0602`; it must exclude known Bolt, Unifying, Nano, and Lightspeed receiver product IDs and correlate the product with a standard mouse collection before opening the HID++ endpoint. Never replace this with a Logitech vendor-only matcher.

## Device rule

Treat these as **different devices**, not one “MX Master”:

| Device | HID++ collection | Gesture / extra-button notes |
|---|---|---|
| MX Master 3 | Unifying `0x4082`, BLE `0xB023`. Same HID module as 3S. | Gesture CID `0x00C3`. No 3 on this Mac; inferred from Solaar/logiops. |
| MX Master 3S | BLE `0xB034`, Bolt `0xB043`. Nested `0xFF43` / report `0x11`. | Same CIDs as Master 3. Thumb gesture `0x00C3`. |
| MX Master 4 | BLE: vendor report `0x11` on the mouse device (page `0xFF43`), not a separate `0xFF00` collection. Bolt receiver `C548` is not the mouse (slots; see `dev/logi-bolt-receiver.md`). | **Haptic button** is HID button 7 (`0x40` on report `0x02`) / CID `0x01A0`. **Gesture button** is CID `0x00C3` (same thumb button as 3S). Divert it `0x33` when it owns Gestures. Do not call it Side. |
| Generic Logitech HID++ mouse | Audited HID++ vendor collection correlated with a standard mouse collection, or a Bolt slot classified as a mouse. | Capabilities and CIDs come from live feature/Reprog probes. Unknown controls map to stable Extra slots; primary clicks stay native. |
| Generic game controller | None. GameController `GCExtendedGamepad` only. | Face, d-pad, sticks, bumpers, analog triggers, Menu / Options / Home. No DualSense touchpad. Labels from `GamepadLayout`. |
| MX Mechanical / Mini | BLE `0xB366` / `0xB367`. Nested HID++ on the keyboard collection (report `0x11`). | Settings only (backlight, effect, battery). Do not divert keys. |

3S + 4 (and multiple generic Logitech mice) are allowed through per-device readers claimed from one shared mouse module. Do not collapse them into one snapshot or let multiple readers claim the same endpoint. The keyboard stays on its own `MXKeyboardReader`. Shared code should stay at “send a HID++ report” / “list HID devices” / hold-to-swipe.

## Hard constraints

- Never call `IOBluetoothDevice.pairedDevices()`. It has corrupted the heap on this Mac (`libmalloc` / `EXC_BREAKPOINT`).
- Never `IOHIDManagerOpen` with `kIOHIDOptionsTypeSeizeDevice` on Logitech mouse or HID++ managers.
- Do not open the standard Logitech mouse collection (usage page `0x01` usage `0x02`) just to watch buttons. That can steal the system pointer.
- Reprog Controls V4 `setCidReporting` flags are value + valid pairs, not “0x01 divert / 0x02 persist / 0x04 raw XY”. Solaar hold-only gestures use **`0x33`** (divert+valid + rawXY+valid). Persist is `0x04`/`0x08`. Force raw XY is `0x40`/`0x80`. Packet is CID, flags, remap, and optional high flags. Analytics reporting is high-byte `0x03`. Do not send persist or force-raw-XY. Clear with `0x22`, not `0`. The Master 4 haptic pad also needs Force Sensing `0x19C0` threshold `0x15A3`; press events often arrive as analytics, not diverted-buttons.
- Debug builds must stay signed with the Apple Development identity (`DEVELOPMENT_TEAM = XXA24FWXDW`) so Accessibility and Input Monitoring persist across rebuilds. Do not switch back to ad-hoc (`CODE_SIGN_IDENTITY = "-"`).
- Never upload or publish without explicit approval.
